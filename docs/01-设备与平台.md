# 01 设备与平台

先把这台机器摸清楚，后面所有方案都是围绕这些限制设计的。

## 硬件与系统

| 项 | 值 |
|---|---|
| 型号 | `MagicProjector_A1C`（天猫魔屏） |
| 系统 | Android 5.1.1（API 22），YunOS TV 定制 |
| 内核 | Linux 3.14.29，构建于 2023-02-21 |
| 内存 | 957 MB（实际可用约 300–400 MB） |
| 分辨率 | 1280 × 720 |
| 构建标签 | `MBX/MagicProjector_A1C/...:user/test-keys` |

注意：`test-keys` 只是构建标签，**不代表签名用的是 AOSP 测试密钥**。实测框架签名是阿里云 TV 的私钥，见下。

## 签名与权限（决定了哪些事做不了）

框架 `framework-res.apk` 的签名证书：

```
Subject: EMAILADDRESS=Jason.xuf@alibaba-inc.com, CN=Jason, OU=YunOSTV,
         O=Alibaba, L=Hangzhou, ST=ZheJiang, C=CN
SHA-256: 71b5c58bbce7cfa095809aa5714b71b20df95f06938ab8546696e0f768975515
```

对比 AOSP 公开测试密钥（`platform.x509.pem`）：

```
SHA-256: C8:A2:E9:BC:CF:59:7C:2F:...:51:19:2A:B8
```

**两者不同**，所以：

- 签不出平台签名 → `SHUTDOWN`、`REBOOT`、`WRITE_SECURE_SETTINGS` 等签名级权限拿不到
- `sharedUserId="android.uid.system"` 同样不可行
- 把 APK 放进 `/system` 走系统应用路径也不行（`/system` 只读）

实测 shell 执行 `am start -a android.intent.action.ACTION_REQUEST_SHUTDOWN` 会被拒绝：

```
java.lang.SecurityException: Permission Denial: ... requires android.permission.SHUTDOWN
```

## Root 情况

- 出厂无 `su`，`ro.build.type=user`，`ro.debuggable=0`，SELinux **Enforcing**
- 内核 3.14.29 受 **Dirty COW（CVE-2016-5195）** 影响，可提权到 `uid=0`（域为 `shell`）
- 但 `/system` 无法 remount（`mount -o remount,rw /system` 返回 `Invalid argument`），装不了永久 su
- Dirty COW 只改页缓存，**重启即失效**，每次开机需要重跑一次提权脚本

## 已知不可行的事

| 想法 | 结果 |
|---|---|
| 用平台签名拿 SHUTDOWN | 签名私钥在厂商手里，拿不到 |
| `/system` 挂可写装 su | SELinux 拒绝 remount |
| 应用调用 `goToSleep()` | 需要 `DEVICE_POWER`（签名级） |
| 无障碍拦截电源键 | POWER 在输入队列阶段就被系统消费，无障碍收不到 |
| 改 keylayout 重映射按键 | 文件在只读分区，Dirty COW 的修改重启即失效 |
| 刷 Magisk / 自定义 recovery | 无可用 recovery，bootloader 未解锁 |
